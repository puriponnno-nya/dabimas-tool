### 照合のしかた（文字起こし前提）

コメント欄には、iPhoneショートカット→Googleアプリで文字起こしした文を貼り付ける。
文字起こしの精度は完璧ではないため、次の順で照合する（`app.js` の `cmNorm`／`bestMatch`／`classify`）。

1. **正規化**：全角→半角への統一（NFKC）、空白・改行・句読点・記号類の除去、よくあるゆらぎの吸収（例：凄→すご、巧→上手、適性→適正）。
2. **複合コメントの完全一致**：スピードの長文など2〜3文で1件のものは、長い組み合わせから先に、完全一致だけで試す（部分一致だと1文だけに一致して残りの文を飲み込んでしまうため）。
3. **文中の原文をすべて拾う**：1行に複数のコメントがスペース区切りで並んでいる場合（文字起こしで句読点が落ちた場合など）は、文の中に含まれる対応表の原文をすべて分類する。
4. **あいまい照合**：どれにも含まれない文は、文字バイグラムの Dice 係数が 0.75 以上なら採用（誤字が1〜2文字あっても拾う）。
5. どれにも当てはまらない文は **「未分類」** として表示する。ユーザーが手で分類を選び直せる。

## BC印比較によるスピード測定（参考情報。v1では測定機能として実装しない）

すべて**参考・未検証**。公式が数値を明示した資料は確認できていない。**v1はこの測定を行わない。**参考情報としてここに記録するだけ。

- 目的：特別調教師才能などのスピード上昇効果を「芝一杯◯本分」で測る
- 手順：条件を完璧に揃えた2頭を用意し、1頭目には測定対象の才能を付け、2頭目には「芝一杯調教」を1本ずつ追加で付けて、それぞれ「ひとりでBC」に登録する。2頭の印が釣り合うまで芝一杯調教の本数を増やし、釣り合った本数で才能の効果を表す
- 注意点（変数のコントロール）：
  - **内枠優位**：能力が全く同じ場合、内枠（出走表の左側1・2番目）の印が厚くなる。内外の枠順を入れ替えて確認する
  - **コースと騎手の固定**：騎手の得意コースの影響を受けない新潟競馬場などを選び、ランクの高い同等クラスの騎手を乗せる
  - **隠し得意距離**：距離適性範囲内で「特定の1距離のみスピードが高まる」という裏仕様があるとされる。複数の距離で印を比べる
  - **調子の固定**：発揮条件に「好調」が含まれる才能を測る場合、ベスト馬体重＋50kgの状態で藤枝厩舎の「馬じゃらし」を使い、調子を「好調（上り9割）」に固定する
- 出典：Perplexity／NotebookLMまとめ（2026-11-14）。貼り付け文にURLは含まれていなかったため、出典URLはなし

## 測定の絞り込み（測定メモ）

すべて**ユーザー検証による推定・未確定（参考・未検証）**。公式が数値を明示した資料は確認できていない。**数値は断定しない。**測定メモによる絞り込みは参考表示だけ。

### 考え方

- **入厩前と入厩後（未調教）のアルファベット（SP/STランク）とコメントで推定して保存する。**これが測定の出発点。レコード自体がその記録になる
- **馬を選んで、調教した結果を測定メモに1件ずつ記録する。**記録するもの：解析日・週、段階（入厩前／入厩後）、対象（スピード／スタミナ）、調教の種類（芝一杯／ダート一杯／ダート併せ／鬼ダート／鬼ウッド／その他）、調教本数、その時点のSP/STランク、測定用コメント、変わった内容（コメント変化／スペースあり／ランク変化／その他）、メモ。対象の指定がない旧記録はスピードとして扱う。入力はボタン／タップ選択が中心で、時期・本数・ランクなどは次の記録に引き継がれる
- **スピードは、測定用コメントとその時点のSPランク、メモリから、到達率の参考範囲を出し、最大値の候補範囲を参考として絞る**
- **スタミナは、コメントによる絞り込みを廃止し、ダート調教による測定法で最大ST候補を出す**（下記「ダート調教によるスタミナ測定」参照）。BC登録の4コメントはスピード到達率の指標で、スタミナに読み替える根拠は確認できなかった（2026-11-15 Perplexity調査）
- **スピード側は、同じ対象の記録が複数あれば、各記録の候補範囲の重なり（共通部分）を取る。**重なりが無くなれば「記録同士が食い違っています」と表示し、数値範囲は出さない
- 1件目は入厩前（または入厩後・未調教）の状態を入れる。2件目以降は調教した結果を入れる。SPランクがE→Dに変わった場合などは、変わった内容に「ランク変化」を選ぶ

### 到達率から最大値の候補範囲を絞るしかた（スピードのみ、参考のみ）

- 到達率＝現在の値÷最大値。現在のSPランク範囲を到達率で割って、最大値の候補範囲を参考として出す（`app.js` の `narrowByTarget`）
- 例：メモリ2などで「BC登録は　まだ先ですね」（スペースあり）なら到達率75%以上・85%未満、「完成まであと一息」なら85%以上。メモリ1・超早熟では「完成まであと一息」が75%、「準備はできた」が85%
- 到達率の区切りが資料で未確認の組み合わせ（例：メモリ2などの「準備はできた」、メモリ1の「BC登録はまだ先」）は、絞り込みの数値範囲を出さない。その旨を表示する
- 初期候補範囲（入厩前後のランクから）と絞り込んだ範囲が食い違う場合は、どちらかの読み・条件が未確定の可能性があると表示する（参考・未検証）。記録同士の候補範囲に重なりが無い場合は「記録同士が食い違っています」と表示する。矛盾を解消する数値は出さない
- 「準備はできた」は全能力が最大になった意味ではない（スピードビー号ではSP C・ST Eでも出た）

### ダート調教によるスタミナ測定（2026-11-15 Perplexity調査）

すべて**ユーザー検証による推定・未確定（参考・未検証）**。公式が数値を保証した資料はない。実装は `app.js` の `narrowStaminaDart`、`data/ranks.json` の `measureNarrowing.staminaDart`。

- **基本**：入厩直後のスタミナは、成長タイプ（メモリ）に関係なく最大値のおよそ50％とされる。STにはSPのようなメモリ別の「蓋」は無いとされる
- **手順**：入厩直後にSTランクを記録する → ダート一杯を1本ずつ行い、その都度解析する → STランクが初めて変わるまでの本数nを記録する
- **計算**：入厩時ST初期値＝境界値T−n（Tは変わった先のランクの下限：D＝55、C＝70、B＝85、A＝100）。最大ST候補＝2×初期値 または 2×初期値＋1（2候補。偶数・奇数の区別はこの測定だけではできない）
- **例**：入厩時Dでダート一杯5本でC→初期値65→最大ST候補130／131。入厩時Eで1本でD→初期値54→108／109
- **調教の数え方**：ダート一杯1本＝ST＋1（確定上昇範囲）。馬なり・強めは上昇が確定ではないので数えない。ダート併せは基本＋1だが併せ効果でずれる場合がある。鬼ダートはST＋2で境界をまたぐため初期測定には不向き。鬼ウッドはSP＋1・ST＋1
- **使わないもの**：調教抜けの境界（通常100まで等）は古い資料と新しい資料で差があり未確認のため、数値として使わない
- **ツールの扱い**：入厩時STランクは、測定メモの中で「入厩前」以外で最初にSTランクが記録された記録のものを使う。ダート一杯の記録でSTランクが初めて上がった記録から計算する。まだ変わっていなければ「まだ候補は出せない」と表示する
- 出典：appligame「久しぶりに能力測定の話①」（2023-02-15公開、2023-03-03更新）http://appligame.xyz/dabimas/archives/42563、たかな channel 動画（2026-03-20）https://www.youtube.com/watch?v=JNcIF2xVd30、appligame「能力測定とかの雑記①」（2019-11-20公開）http://appligame.xyz/dabimas/archives/30505

## 測定用コメントの変化（到達率とメモリ）

すべて**ユーザー検証による推定・共有情報（参考・未検証）**。公式発表はない。**v1は数値測定の機能を作らない。**コメントの検出と、到達率の参考表示だけ。

### 調教本数で一律に変わるのではない

- 「調教○本で一律に変わる」という固定本数ではない。**スピードの最大値に対する到達率と、成長タイプ（メモリ）で変わる**
- 全馬共通の「○本で変わる」は確認できていない。成長メモリや測定の起点をそろえる必要がある
- 通常調教は入厩後に可能になる（公式ビギナーガイド https://dabimas.jp/beginner/ で確認）。入厩前に何本追ったら変わるかではなく、**入厩前の解析と、入厩後に調教を進めた解析を比較する**形になる
- 「入厩前の能力欄は最大能力、入厩後は育成中の能力を示す」という説明はユーザー攻略記事によるもの。公式による数値仕様の説明ではない（今回確認できた範囲では）

### 到達率による変化（メモリで読み方が違う）

| スピードの到達率 | メモリ2などの測定時 | メモリ1・超早熟 |
| --- | --- | --- |
| 75%未満 | 「BC登録はまだ先ですね」（スペースなし） | 「まだ先」段階 |
| 75%以上・85%未満 | 「BC登録は　まだ先ですね」（スペースあり） | 「完成まであと一息でしょうか」 |
| 85%到達 | 「完成まであと一息でしょうか」へ変化 | 「準備はできたようですね」へ変化 |

- **メモリ1では、75%が「あと一息」、85%が「準備はできた」になる。**他のメモリと同じコメント名で判定しないこと
- **メモリ2などで「準備はできたようですね」になる到達率は、今回の資料では未確認。**ツールもその旨を表示する

### スペースの有無が測定上の区切り

- 「BC登録はまだ先ですね」と「BC登録は　まだ先ですね」は、文字が同じでも**スペースの有無が測定上の区切り**として扱われている
- ツールは、正規化（スペース除去）で消す前に、元の文のスペースを判定に使う（`app.js` の `detectMeasureSentence`）。「BC登録は　まだ先ですね」（スペースあり）を別カテゴリとして検出する
- **文字起こしでスペースが落ちると区別できない。**その場合は「スペースなし」として検出される。貼り付け文のスペースを確認すること
- スペースが入る本数の例：スピードA到達後、スピード調教10回目ではスペースなし、11回目でスペースありになったと報告がある（スピード147と判定）。**入厩から11本という意味ではない**

### 追加した理論

- **完璧な配合**：見事な配合と面白い配合が同時に成立すること。Appliv式（両者の面白系統7種以上＋見事一致）を主とする。dbms-go.netは「種牡馬自身が面白い配合で配合されていることが必須」とも書くが、種牡馬自身の配合は血統データだけでは確認できないため、その点は未確認として注記する。効果の数値は未検証のため表示しない
- **超完璧な配合**：見事な配合が成立し、かつ面白い配合の8頭の親系統が8種類すべて異なること。効果の数値（147-127など）は条件付き実測値のため表示しない
- **奇跡の配合**：完璧な配合の成立が前提。さらに4×3のクロス：種牡馬側4代前（子の血統表で4・5・7・8番目）と繁殖牝馬側3代前（子の血統表で13番目の母母父のみ有効）に同じ祖先がいること。3代前が母父父では不成立。4代前が種牡馬側3代（父母父）では不成立。名前の一致で判定するが、同馬の因名違い・年号違いの表記は正規化して同一視する（`normalizeCrossName`）。兄弟クロス（異なる馬同士の全兄弟）は分からず、その限界を注記する。牝馬クロスが4代前でも無効という出典もあるが、祖先の性別データがないため判定できず、注記する。配合掲示板には表示されない隠し要素とされる。因子別の効果数値（短＝スピード+2など）は走・中因子が撤回／未検証のため表示しない
- **奇跡の配合の検証と修正（2026-11-14）**：ユーザーの送った画像の配合ルートで、最終配合が画像では「奇跡の配合」なのにツールは「完璧な配合」と判定していた。検証の結果、4×3クロス自体はダンチヒで成立していた（父側「ダンチヒ」父父母父・4代前 × 母側「ダンチヒ1992」母母父・3代前。位置の解釈は正しかった。出典3件も再確認し、母側3代前は母母父のみ・父側4代前はどこでもよいことで一致）。原因は名前の完全一致だけで比べていたことで、同馬の表記違いを見逃していた。修正：クロス判定・インブリード表示・血統表の「DBにあり」照合で `normalizeCrossName` を使うようにした。修正後は最終配合が奇跡の配合になり、画像の配合10件すべてのラベルが画像と一致する（ハーネス M17〜M20）。ルートBCの配合は修正前から奇跡の配合で、クロスはグロースターク（父側父母母父・4代前 × 母側母母父・3代前）
- **危険な配合**：1×N（父馬名または母馬名そのものが相手方の血統に出る場合）または2×2（父方2代＝父父と母方2代＝母父に同じ祖先が出る場合）のクロスが発生すると成立。父母・母母の名前は血統データに牝馬が出ないため分からず、2×2は父父×母父の一致だけを判定する。受胎率20%という数値は印象論で未検証のため表示しない。兄弟姉妹クロスは血統表に牝馬が出ないため判定できない場合があることを注記する

### 至高の配合の追加（2026-11-15 Perplexity調査）

- **至高の配合**：2026-11-15のPerplexity調査で、因子を数える範囲（クロスを構成する出現箇所だけ）と配置の確認例2通りが示されたため、確認済みの範囲に限って判定に入れた。条件は上の表の通り。判定のしかたは `app.js` の `checkSupreme`／`foalAncestorOccurrences`。ハーネスは `scripts/test-pedigree.js` の M50〜M54。配置が確認済みの2通りでなく、3・4・5代に同じ馬がいるだけの場合は「判定しない」と表示する。因子が6種類に届かない場合は、その旨と種類数を表示する。使用する同一種牡馬の種類数は3種類限定ではない（4種類使用の成立報告あり）ため、出現箇所の数には上限を設けていない。見事・完璧などの親系統条件は不要とされるため、判定には含めない。効果は未解明のため数値は表示しない

## 自分の馬（自家生産馬：2代目以降の配合・ステップ4：参考・未検証）
