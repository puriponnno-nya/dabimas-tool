# ダビマス能力判定ツール 仕様 v2（v1）

## 目的

ダビマスの所有馬の能力を、コメント文と能力ランクから判定・記録する。
**能力判定を先に作る。配合計画は後回し。**

## 対象

- iPhone・Safariで使う1画面の静的ツール（`index.html`＋`styles.css`＋`app.js`）
- 追加課金・有料API・サーバーなし
- 仮データのみ。実牧場データは入れない

## 入力の前提（重要）

- コメント欄には、**iPhoneショートカットでスクショを読み込み、Googleアプリで文字起こしした文を貼り付ける**ことを前提とする。
- スクショの直接読み取り（OCR）はしない。Perplexityではファイルのアップロード上限でスクショ読み取りができなかったため、このワークフローになった。
- 文字起こしの精度は完璧ではない。そのため判定は完全一致ではなく、正規化＋部分一致・あいまい照合で行う（`docs/rules.md` 参照）。

## 機能（v1）

1. 馬レコードの作成・一覧・編集・削除
   - 項目：馬名（必須）、年齢、性別（牡／牝／セン／不明）、解析時期、解析タブ、解析時所属、メモリ、成長タイプ（メモリの数字＝バーの目盛り 1〜6。1＝最も早寄り、6＝最も遅寄り。対応：1→早寄り、2→早寄りの中間、3→中間、4→遅寄りの中間、5→遅寄り、6→遅寄り（最遅）。数字（growthNum）とことば（growth）の両方を保存・表示し、バー表示も出す）、SPランク（A〜E／未入力）、STランク（A〜E／未入力）、根性・気性・体質ランク（A〜E／未入力）、脚質、距離適性、適応力、博士コメント・特徴・目標レース・解析コメント（定型文の4つの文章）、コメント文（貼り付け）、メモ、手修正（未分類文の手分類）
   - 成長タイプは推定計算には使わない。表示のみ（例：成長タイプ 2/6 早寄りの中間 ■■□□□□）
   - ID・作成日時は不変、更新日時で更新する
2. 定型文の貼り付け読み取り（`parsePasted`）
   - 「定型文を貼り付ける」欄に、馬体解析の定型文をまるごと貼る。「馬名：」「年齢：」「解析時期：」「解析タブ：」「解析時所属：」「スピード：」「スタミナ：」「根性：」「気性：」「体質：」「メモリ：」「脚質：」「距離適性：」「適応力：」の行を読み取り、ランクは A〜E のみ採用する
   - 「博士コメント：」「特徴：」「目標レース：」「解析コメント：」の見出し以降は複数行の文章として読み取り、4つの欄と判定用のコメント欄（4つをまとめたもの）に入れる。「解析コメント：」がない定型文も従来通り読める
   - **「メモリ：N」は成長タイプの数字。**N が 1〜6 なら成長タイプにも反映する（1→早寄り、2→早寄りの中間、3→中間、4→遅寄りの中間、5→遅寄り、6→遅寄り（最遅））。メモリ欄自体も残す。メモリ欄に 1〜6 を手で入れたときも成長タイプに反映する
   - 旧レコードとの互換性：成長タイプがことばだけの旧レコード（growthNum なし）も読める。ことばから数字を逆引きして表示する（例：「早寄りの中間」→2/6）。growthNum が 1〜6 以外のJSONは読み込み時に拒否する
   - 全角・半角の「：」「:」どちらでも読む。読み取れなかった項目は空欄のまま手入力できる。読み取れた項目と読めなかった項目をメッセージで表示する
   - 従来の個別入力も残す。定型文を使わずに直接入力してもよい
2. コメント分類の表示：素質 tal／将来 fut／特徴 fea／期待と条件 exp
3. 測定用コメント3種の検出のみ（数値・到達率は判定しない）
4. SP/ST 候補範囲の参考表示（ランク範囲＋素質・タイトル文の条件。**参考・未検証**と明記）
5. ブラウザ内保存（localStorage、キー `dabimas-ability-v1`）
6. JSON書き出し・読み込み
   - 書き出し：全件。読み込み：全件置き換えのみ。検証あり（version 2、レコード形式、ID重複を検査。version 1 のJSONも読める）
   - 不正なJSONは拒否して、既存データは変えない
7. 未分類文の表示と手修正
   - 照合できなかった文は「未分類」として表示する
   - 未分類の文ごとに分類（tal／fut／fea／exp）を手で選べる。選ぶとその場で判定に反映され、保存すると手修正も一緒に保存される
   - コメント文を編集すると手修正はリセットされる（原文が変わるため）
8. 繁殖計画の記録（ステップ1）
   - 項目：計画名（必須）、父馬名、母馬名、ステータス（計画／予約／実行済み）、メモ、作成日、更新日、ID
   - 父馬・母馬は名前のテキスト入力、またはステップ2の種牡馬データベース検索からの選択。将来の紐付けのため、データ構造に sireHorseId／damHorseId を用意しておく（今は常に null＝未紐付け）。DB検索からの選択は sireDbIndex／damDbIndex（データベース内の番号。未選択は null）で残す
   - 計画フォームの父馬・母馬の欄にもデータベース検索を直接組み込む（2026-11-14追加）。欄に馬名を入れると部分一致の候補が先頭10件まで出て、選ぶとその欄に入りDB番号も残る。欄の下の折りたたみで子系統・因子・非凡・天性でも絞り込める。条件なしでは候補は出ない。候補を選んだ馬は欄の下に「DBから選択：馬名（子系統 …）」と表示され、名前を手で直すとDB選択が外れて「名前だけの入力です」と表示される。DBにない馬は名前だけの入力でも登録できる。従来の検索セクションからの選択も残し、そちらを選んだ場合も同じ表示になる
   - 保存はブラウザ localStorage、馬データとは別のキー `dabimas-breeding-v1`
   - JSON書き出し・読み込みに繁殖計画も含める。繁殖計画のない旧形式のJSONも読み込める（その場合は既存の繁殖計画は残る）。不正な繁殖計画は拒否し、既存データは変えない。DB番号なしの旧計画も読める。DB番号が負の数や整数以外のJSONは拒否する
   - 配合のシミュレーションはしない。未確定の配合効果を断定表示しない。子の血統表・配合理論の確認はステップ3（下の10）で追加した
   - 参考リンク（外部サイトへのリンクだけ。データのコピーや取り込みはしない）：たかなさんの紹介記事 https://note.com/takana_mmdd/n/nff464f9f1292、DBMS SP/STチェッカー https://takana666.github.io/DBMS_SPST_checker/、至高種・組合せ検索 https://takana666.github.io/DBMS_shikou_checker/、たかなさんのX https://x.com/mmmmdd_tw。データはたかなさんのもので毎週金曜夜にダビマス全書から自動取得。リンク先が使えなくなる可能性があり、いずれ自作で同じ機能を入れる予定
9. 種牡馬データベース検索（ステップ2・2026-11-14追加）
   - ユーザーがダビマス全書／たかなさんのDBMS種牡馬データ検索から取得したCSV（2026-11-14入手。3021行）を `scripts/convert-stallions.py` で `data/stallions.json`（3.9MB）に変換して読む。データのコピーやスクレイピングではなく、ユーザーが渡したファイルを読み込むもの。元のCSVはリポジトリに入れない（重い・ユーザー提供ファイルのため）
   - 残す項目：馬名、link（URLの数字IDだけ）、因子1〜3、子系統、距離、成長、適応力、体質、気性、脚質、実績、底力、安定、非凡種類、非凡、天性、発揮効果（先頭200文字まで）、5代血統の祖先15件（名前・親系統・子系統・因子1・因子2）。空欄はそのまま。非凡なし1651件、天性なし2922件。同名の別バリエーションは別レコードのまま
   - 検索：馬名の部分一致、子系統（選択式）・因子・非凡・天性での絞り込み。条件なしでは0件（3021件を全部出さない）。結果は先頭50件まで表示
   - 検索結果の一覧から、父馬・母馬として繁殖計画に選べる。選んだ馬の血統（5代）と親系統・子系統、因子・非凡・天性を表示できる。計画の一覧からも父馬・母馬の血統を見られる。発揮効果は先頭のみの参考表示
   - 配合の効果を断定する表示はしない。配合理論の判定はステップ3（下の10）
   - 出典はユーザー検証・参考と明記する
   - `data/stallions.json` は `fetch` で読むため、サーバー経由で開く必要がある。`file://` で開いたときは検索は使えない（その旨を表示する）
10. 子の血統・配合理論の確認（ステップ3・2026-11-14追加）
   - 父馬・母馬の両方を種牡馬データベース検索から選んだ繁殖計画だけが対象。計画カードに「子の血統・配合理論を見る」（折りたたみ・既定は閉じる）が出る。名前だけの計画や片方だけDB選択の計画には出ず、「DBから父・母を選ぶと確認できます」と表示する
   - 子の血統表（5代）：子の父＝父馬名、母＝母馬名。15位置は父馬・母馬の anc から組み立てる（父父＝父馬anc[0]、父父父＝父馬anc[1]、父父父父＝父馬anc[2]、父父母父＝父馬anc[5]、父母父＝父馬anc[8]、父母父父＝父馬anc[9]、父母母父＝父馬anc[12]、母父＝母馬anc[0]、母父父＝母馬anc[1]、母父父父＝母馬anc[2]、母父母父＝母馬anc[5]、母母父＝母馬anc[8]、母母父父＝母馬anc[9]、母母母父＝母馬anc[12]）。各祖先は名前と親系統を表示し、名前がデータベース内の馬名と完全一致する場合は「DBにあり」と表示し、「詳細」でその馬の血統・詳細を見られる
   - 配合理論の判定（すべて参考・未検証。断定しない。根拠も一緒に表示する。親系統が空の祖先は無視する）。面白い配合：父馬・母馬それぞれの 父(anc0)・父母父(anc5)・母父(anc8)・母母父(anc12) の計8頭の親系統の種類数が7種類以上。見事な配合：父馬の 父父母父(anc4)・父母母父(anc7)・母父母父(anc11)・母母母父(anc14) の4頭の親系統の多重集合と、母馬の 父(anc0)・父母父(anc5)・母父(anc8)・母母父(anc12) の4頭の親系統の多重集合が並べ替えで一致。よくできた配合：上記2つの4頭集合の共通する親系統の種類数が3種類以上で、見事な配合でない場合。完璧な配合は判定しない（見事＋面白いの同時成立だけでは断定できず、種牡馬自身の条件があり未確認のため。注記だけ出す）。至高の配合は判定しない（未確認）。危険な配合は判定しない（根拠が不確か）。どの理論も成立しない場合はその旨を表示する。出典（ユーザー攻略記事。公式仕様ではない）：Appliv Games https://games.app-liv.jp/archives/232008 と https://games.app-liv.jp/archives/198428、dbms-go.net「完璧な配合」 https://dbms-go.net/配合解説/完璧な配合/
   - インブリード（クロス）の表示：父方（父馬由来の7位置）と母方（母馬由来の7位置）の両方に出る同じ祖先名を、世代「父方○代 × 母方○代」（父父・母父＝2代、父父父・父母父・母父父・母母父＝3代、ほか＝4代。父・母そのもの＝1代）と因子つきで一覧表示する。父馬名・母馬名そのものが相手方の祖先に出る場合も同じ扱い。クロスがない場合はその旨を表示する
   - 表示は折りたたみ（`<details>`、既定は閉じる）に入れ、理論・参考表示は既定で非表示の方針を守る

11. 自分の馬（自家生産馬：2代目以降の配合・ステップ4・2026-11-14追加）
   - 配合計画の子の血統・配合理論の表示から、その子を「次の配合の親」として登録できる。計画カードに名前（初期値は計画名＋「の子」）・性別（牡／牝／不明）の入力と「子を登録する」ボタンが出る。登録した子は自分の馬として、馬・繁殖計画とは別のキー `dabimas-own-horses-v1` に保存する。能力判定ツールの登録馬とは別扱いで、繁殖計画ツールの中だけで使う
   - 自分の馬は、次の繁殖計画の父馬・母馬の欄から、データベースの3021頭と一緒に候補に出る（「【自家生産馬】」と区別がつく表示。性別・世代・両親も表示）。牡は父馬欄、牝は母馬欄、不明は両方に選べる。因子・非凡・天性・子系統で絞っている場合、自分の馬はその情報を持たないため候補に出ない。自分の馬の一覧からも「父馬に選ぶ」「母馬に選ぶ」（性別に合う役割だけ）ができる
   - 子の血統（anc 15件）は、両親の血統を1代ずらしたものとして持つ（子の血統表の15行をそのまま anc にする。0番目＝父そのものは、父馬自身の子系統・因子1・因子2を入れ、親系統は父馬の父の親系統＝父馬自身の親系統（父系で受け継がれる）で補う）。自分の馬を親に選んだ計画では、その子の血統から子の5代血統が同じ仕組みで組み立てられ、配合理論とインブリードも判定できる。子を登録→その子を親に選ぶ→また子を登録、と繰り返すと3代目以降も続けられる。世代数はDB馬を1代目として、子の世代＝両親の世代の大きい方＋1
   - 自分の馬の一覧・削除ができる。一覧では名前・性別・世代・両親と、5代血統（参考・折りたたみ）を表示する。削除した馬を親に選んだ計画の子の血統・配合理論の確認はできなくなる（計画自体は残る）
   - 配合理論の効果を断定しない。すべて「参考・未検証」と明記する。JSON書き出し・読み込みに自分の馬も含める。自分の馬のない旧形式のJSONも読み込める（その場合は既存の自分の馬は残る）。`scripts/test-own-horses.js`（Nodeハーネス、42件）で自動確認する

12. 1つの計画での多世代の配合（ステップ5・2026-11-14追加）
   - 計画の中に世代（ステップ）の列を持たせる。第1世代＝今までの計画（父・母→子）。第2世代以降は、前の世代の子を親として同じ計画の中で続ける。何世代でも追加できる
   - 各世代の子の血統・配合理論の表示の下に「次の世代を追加」がある。押すと、前の世代の子がまだ自分の馬として登録されていなければ自動で登録され（子の名前・性別はその世代の欄の値を使う）、その子を親にした次の世代ができる。子の性別が牝なら母に、牡・不明なら父にする（あとで世代の欄から選び直せる）
   - 各世代で、父・母はデータベースの馬と自分の馬（自家生産馬）の両方から選べる。世代の欄に馬名を入れると候補が出て、子系統・因子・非凡・天性でも絞り込める（計画フォームと同じ仕組み）。子の名前・性別は各世代で決められる
   - 計画の表示では世代が第1世代→第2世代→第3世代…の順番に見える。各世代に配合理論の判定（面白い／見事な／よくできた、すべて参考・未検証）と子の5代血統が表示される。新しい配合理論は追加しない
   - 世代の削除もできる（世代が1つだけの計画では、その世代は削除できない。計画ごと削除する）。削除した世代の子は、ほかの計画の親に使われていなければ自分の馬からも一緒に削除される。そのため、その子を親にしていた同じ計画内の世代は、子の血統・配合理論が表示できなくなる。その場合は「選んだ父馬・母馬が見つかりません」と表示し、計画自体は残す。削除する前に、その世代の子があとの世代の親に使われている場合は、削除ボタンの近くに「この世代を削除すると、第X世代の子の血統・配合理論が表示できなくなります」と表示する。各世代の欄には、その世代の子があとの世代の親に使われていることも表示する
   - 世代のデータ：`{id, childName, childSex, sireName, damName, sireDbIndex, damDbIndex, sireOwnId, damOwnId, sireHorseId, damHorseId, childOwnId}`。`childOwnId` は、その世代の子を自家生産馬として登録したときのID。自分の馬には、どの世代の子かを示す `generationId` も残す。第1世代の内容は、計画の欄（旧形式と共通の欄）にも写す
   - JSONは version 2。version 1 のJSON（世代の列なし）もそのまま読み込め、第1世代1つとして表示される（旧形式で登録済みの子は、planId で結び付ける）。localStorage（馬・繁殖計画・自分の馬の各キー）の保存も version 2 で書き、version 1 の保存も読める。`scripts/test-generations.js`（Nodeハーネス、30件）で自動確認する

13. 配合ルート図（ステップ7・2026-11-14追加）
   - 計画の世代の列から、世代ごとの父・母・子を図にする（`buildRouteDiagram`／`buildRouteDiagramHtml`）。左が最終の子、右へ行くほど前の世代。第n世代＝1代前、第n-1世代＝2代前…と列を分け、各列の見出しに「第N世代（M代前）」と出す。種牡馬は青系、繁殖牝馬はピンク系の箱で表示する。親から子へのつながりを矢印（←）で示す。前の世代の子が親になっている場合は、その箱に「第N世代の子」と注記する
   - 各世代の配合理論の判定ラベルを、その世代の列に付ける。判定はステップ3・6のもの（`checkMatingTheories`）を使い、一番上のものをラベルにする（優先順：奇跡＞超完璧＞完璧＞見事＞面白い＞よくできた）。どれにも当てはまらなければ「配合理論なし」。危険な配合だけが当てはまる場合は「配合理論なし」に危険な配合の注記を付ける。すべて「参考・未検証」と明記し、配合の効果を断定しない
   - 図は iPhone（縦画面）でも見やすいよう、横にスクロールできる（`.route-scroll` の `overflow-x: auto`）。図と今までの一覧表示は両方残し、図は計画カードの上部に折りたたみ（`<details class="route-diagram" open>`、既定は開く）で出す。世代が1つだけの計画でも図が出る（最終の子＋第1世代の2列）。世代の途中で親が見つからない場合は、その世代の箱に「親が見つかりません」と出し、配合理論は確認できない旨を表示して、計画自体は残す。名前だけの計画も図が出る（箱は名前だけの入力、ラベルは配合理論の確認方法の案内）
   - `scripts/test-route-diagram.js`（Nodeハーネス、13件）で自動確認する。世代の一覧の順番を確認する `scripts/test-generations.js` の N20・N21 は、ルート図（最終→古い世代の順）ではなく世代一覧の見出し（`<h3>第N世代</h3>`）で順番を確認するようにした（判定内容は変わらない）

14. 配合理論のプレビュー（保存前・2026-11-14追加）
   - 繁殖計画の作成・編集フォームで、父馬・母馬の両方が選ばれたら、その場で配合理論の想定を表示する（保存前）。表示は「配合理論の想定（保存前・参考・未検証）」の見出し＋父×母＋成立しそうな理論の一覧（面白い／見事な／よくできた／完璧な／超完璧な／奇跡の／危険な）と根拠（どの親系統・祖先が一致したか）。どの理論にも当てはまらなければ「配合理論なし（参考・未検証）」。すべて「参考・未検証」と明記し、配合の効果を断定しない
   - 判定は保存後の確認と同じ `checkMatingTheories` を使い、表示も保存後の確認と同じ `matingTheorySummaryHtml` から作るので、保存前に見た想定と保存後の判定は一致する。状態の判定（両方未入力／片方だけ／名前だけ／選んだ親が見つからない／両方解決）は DOM を使わない `matingTheoryPreview` で決め、表示は `matingTheoryPreviewHtml` が作る
   - 父馬・母馬のどちらか一方だけしか選ばれていない場合は、もう一方を選ぶよう案内を表示する。名前だけの入力（データベースにない馬）の場合は、血統が分からないため判定できない旨を表示する。選んだ親が見つからない場合（DBが読み込めていない・自家生産馬が削除された）もその旨を表示する
   - 世代の追加（第2世代以降）のフォームでも同じプレビューが出る。各世代の父馬・母馬の欄の下に表示され、判定と表示は計画フォームと同じ関数を使う。世代の欄は選び直すたびに計画が再表示されるため、候補から選んだ場合は再表示時にプレビューが更新され、名前を手で直した場合は入力時に更新される
   - `scripts/test-theory-preview.js`（Nodeハーネス、19件）で自動確認する

15. 複数ルートの統合図解（ステップ8・2026-11-14追加）
   - 別の計画（ルート）の最後の子を、この計画の父・母として選べる。自分の馬（自家生産馬）の候補・一覧・選択済みの表示には、由来の計画名・世代（「計画名」第N世代の子）を付ける。自分の馬の保存データには、登録時に由来の計画名（`originPlanName`）と世代番号（`originGenerationNo`）を記録する。由来が記録されていない旧形式の自分の馬は「由来不明」として扱い、表示も枝の展開もしない。JSON書き出し・読み込みで由来は残る。旧形式の自分の馬を含むJSONも読める（後方互換）
   - 複数ルートの子同士を掛け合わせた計画では、配合ルート図が統合図（`buildMergedRouteDiagram`／`buildMergedRouteDiagramHtml`）になる。最終の子を根（左端）とし、親を右へたどる木構造で、上の枝が父方のルート、下の枝が母方のルートで、最終の子のところで合流する。父・母が自家生産馬で由来が分かる場合は、その馬を生んだ計画の世代列をたどって枝を展開する（再帰。循環参照は防ぎ、深さは12配合まで）。由来が分からない自分の馬・由来の計画や世代が見つからない馬は、枝なしで箱だけ表示し、その旨を注記する。DBの馬・名前だけの入力・未入力も箱だけ
   - 統合図を使うのは、最終の世代の先祖に別の計画の子がいる計画だけ（`planHasCrossRouteAncestry`）。それ以外の計画は今までの1ルートの図（ステップ7）のまま。統合図は最終の子の血統ルートだけをたどる図で、最終の子につながらない世代は世代の一覧で確認する
   - 各配合の箱には由来の計画名と第何世代の子かを付け、各配合の配合理論の判定ラベル（ステップ3・6の判定で一番上のもの。優先順：奇跡＞超完璧＞完璧＞見事＞面白い＞よくできた。どれにも当てはまらなければ「配合理論なし」）を付ける。すべて「参考・未検証」と明記し、配合の効果を断定しない
   - 図は iPhone（縦画面）でも見やすいよう、横にスクロールできる（`.route-scroll` の `overflow-x: auto`。箱は `flex: 0 0 auto` で縮まない）。図と今までの一覧表示は両方残し、図は計画カードの上部に折りたたみ（`<details class="route-diagram" open>`、既定は開く）で出す。見出しは「配合ルート図（複数ルート統合）を見る（参考・未検証）」
   - `scripts/test-merged-route.js`（Nodeハーネス、16件）で自動確認する。テストの配合はユーザーの送った画像の配合ルート（2026-11-14）に沿う。画像の10頭（グラスワンダー、モントブルック、ミルジョージ、ラブスイーツ、シーキングザゴールド、タケホープ、グロースターク、サクラクレアー、ダンチヒ（DBは「ダンチヒ1992」）、メモリーレーン）はすべてデータベースにあり、画像の配合10件を5つの計画（ルートA・ルートB・ルートC・ルートBC・最終配合）で作る。画像で名前のない箱はすべて自家生産馬（配合の子）なので代役の馬は使わない。画像の配合理論ラベルとツールの判定ラベルが一致するかは求めない（判定はDBの血統から行う。参考・未検証）。テスト用の計画・馬はハーネス内のメモリだけに作り、リポジトリのデータには残さない

## データ

- `data/comments.json`：コメント対応表 CMT／CMX（旧プレビューから統合）。全件網羅ではない
- `data/ranks.json`：ランク範囲・素質・タイトル条件（2018年資料由来・参考・未検証）
- `data/stallions.json`：種牡馬データベース（3021件・3.9MB）。ユーザーがダビマス全書／たかなさんのDBMS種牡馬データ検索から取得したCSV（2026-11-14入手）を `scripts/convert-stallions.py` で変換したもの。ユーザー検証・参考。元のCSVはリポジトリに含めない。キー対応表：n=馬名、link=全書URLの数字ID、f1〜f3=因子1〜3、chi=子系統、dist=距離、growth=成長、adapt=適応力、phys=体質、temp=気性、style=脚質、record=実績、base=底力、stab=安定、hk=非凡種類、hibon=非凡、talent=天性、eff=発揮効果（先頭200文字まで）、anc=5代血統の祖先15件（[名前, 親系統, 子系統, 因子1, 因子2]。末尾の空欄は省く）。ancestors=祖先15件の血統位置名
- `app.js` には `data/*.json` と同じ内容の内蔵コピーがある（`file://` で開いたときに JSON が読めない場合の予備。正本は `data/*.json`）。ただし `data/stallions.json` は3.9MBあるため内蔵コピーはなし。`file://` で開いたときは検索は使えない
